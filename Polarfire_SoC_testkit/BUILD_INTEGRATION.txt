PolarFire SoC YOLO-Pose 통합 빌드 인수인계
===========================================

1. 개요
------------

검증된 YOLOv8 VNNX 추론 결과를 pose_roi_input_t로 변환하여 비공개
포즈추정 코드의 pose_acquire()/pose_track()에 연결하기 위한 소스 묶음이다.

현재 공개 전달본에는 포즈추정 내부 구현과 헤더가 모두 포함되어 있지 않다.
따라서 Pose 소스를 추가한 뒤 최종 통합 빌드를 수행해야 한다.


2. 전달 파일
------------

  pipeline_main.c
    - 2048x2048 컬러 JPEG 입력
    - 원본 RGB/HWC 버퍼 수명 관리
    - yolo_init()/yolo_detect() 호출
    - 클래스별 Top-1 선택
    - bbox 전체 폭/높이 10% 확장(각 방향 5%) 및 이미지 경계 clipping
    - pose_roi_input_t 변환 후 pose_acquire()/pose_track() 호출

  run_yolov8n.cpp
    - 검증된 VectorBlox VNNX 초기화/추론 구현
    - 통합 API yolo_init(), yolo_detect()
    - YOLOV8N_LIBRARY_ONLY 정의 시 독립 실행용 main() 제외

  postprocess_yolov8n.c/.h
    - 3개 YOLO 출력의 DFL decode, confidence filtering, NMS
    - output channel 수에서 class 수를 동적으로 계산하므로 nc=1/nc=2 모두 지원

  models/pruned_kd_single.vnnx
    - KITSAT3 single Pruned+KD 테스트 모델

  test_images/*.jpg
    - 2048x2048 JPEG 통합 시험 이미지 5장

  vbx_cnn_api_dma64.patch
    - SDK의 실제 DMA mmap 장치를 64 MiB udmabuf-vbx64로 변경하는 패치

  YOLO_INFERENCE_EXAMPLE.txt
    - 재부팅 후 overlay 적용부터 단독 YOLO 추론까지의 Tera Term 예제

  SHA256SUMS
    - 전달 파일 무결성 확인용


3. 기존 단독 YOLO 빌드 기록
---------------------------

기존 Makefile.yolov8n 사용 명령:

  make -f Makefile.yolov8n \
    kit=icicle \
    CC=riscv64-linux-gnu-gcc \
    CXX=riscv64-linux-gnu-g++

기존 빌드 성공 당시 산출물 기록:

  크기       : 약 164 KiB
  아키텍처   : ELF 64-bit RISC-V, RVC, double-float ABI (lp64d)
  동적 로더  : /lib/ld-linux-riscv64-lp64d.so.1
  JPEG       : libjpeg.so.9

통합 바이너리는 Pose 소스 포함 범위에 따라 크기가 달라질 수 있으므로
최종 빌드 후 file/readelf로 다시 기록한다.

  file pipeline-yolo-pose
  riscv64-linux-gnu-readelf -d pipeline-yolo-pose | grep NEEDED


4. 통합 빌드 필수 조건
----------------------

  - pipeline_main.c는 C compiler로 컴파일
  - run_yolov8n.cpp는 C++ compiler로 컴파일
  - 최종 링크는 C++ linker로 수행
  - run_yolov8n.cpp 컴파일 시 반드시 다음 매크로 추가

      -DYOLOV8N_LIBRARY_ONLY

    이 매크로가 없으면 run_yolov8n.cpp의 독립 실행 main()과
    pipeline_main.c의 main()이 중복된다.

VectorBlox SDK에서 함께 사용하는 기존 소스:

  /root/VectorBlox-SDK/example/postprocess/image.c
  /root/VectorBlox-SDK/example/postprocess/libfixmath/*.c
  /root/VectorBlox-SDK/example/soc-c/pdma/pdma_helpers.c
  /root/VectorBlox-SDK/drivers/vectorblox/vbx_cnn_api.c
  /root/VectorBlox-SDK/drivers/vectorblox/vbx_cnn_model.c

링크 라이브러리:

  -ljpeg -lm

추가해야 할 항목:

  - pipeline_main.c가 include하는 Pose 관련 헤더
  - pose_acquire()/pose_track() 및 관련 비공개 구현
  - Pose 구현에서 요구하는 추가 소스와 링크 옵션


5. YOLO-Pose 연결 인터페이스
----------------------------

JPEG 입력:

  dtype     : uint8_t
  color     : RGB
  layout    : HWC interleaved
  shape     : [2048, 2048, 3]
  stride    : 6144 bytes
  padding   : 없음

YOLO 출력 좌표:

  yolov8n_detection_t {
      float x1, y1, x2, y2;
      float confidence;
      int class_id;
  }

Pose 전달 ROI:

  - 원본 2048x2048 이미지 좌표
  - x1/y1: 좌상단, x2/y2: 우하단 inclusive
  - width  = x2 - x1 + 1
  - height = y2 - y1 + 1
  - confidence/class_id 전달
  - 클래스별 confidence Top-1만 전달
  - bbox 전체 크기를 10% 확장하고 이미지 경계로 제한
  - ROI crop 버퍼가 아니라 원본 RGB 이미지와 ROI 좌표를 함께 전달
  - 원본 JPEG decode 버퍼는 pose_acquire()/pose_track() 반환 후 해제


6. DMA64 빌드 조건
------------------

통합 실행에는 다음 64 MiB 장치를 사용한다.

  /dev/udmabuf-vbx64
  size      = 67108864
  phys_addr = 0x00000000c4000000

중요: VBX_DMA_DEVICE 환경변수는 현재 runner의 진단 출력에 사용된다.
실제 mmap 장치는 VectorBlox SDK의 vbx_cnn_api.c에 있는 DMA_DEV가 결정한다.
통합 빌드에 사용하는 SDK 소스는 다음 값으로 빌드되어야 한다.

  #define DMA_DEV "udmabuf-vbx64"

전달된 패치 적용 예:

  cd /root/VectorBlox-SDK
  patch -p1 < /root/Polarfire_SoC_testkit/vbx_cnn_api_dma64.patch

SDK 원본 보존이 필요하면 복제된 별도 빌드 트리에서 패치를 적용한다.


7. 보드 재부팅 후 overlay 적용 순서
-----------------------------------

재부팅하면 동적 overlay가 사라진다. 반드시 아래 순서로 다시 적용한다.

  cd /root/VectorBlox-SDK/example/soc-c
  make overlay

  cd /root/VectorBlox-SDK/example/soc-c/dts
  bash overlay.sh add vbx_dma64.dtbo

확인:

  ls -l /dev/uio*
  ls -l /dev/udmabuf-vbx64
  cat /sys/class/u-dma-buf/udmabuf-vbx64/size
  cat /sys/class/u-dma-buf/udmabuf-vbx64/phys_addr

기본 VectorBlox overlay를 적용하지 않으면 실행 시작 직후 libc 주소 0xc0에서
SIGSEGV가 발생할 수 있다. 실제로 make overlay 적용 후 정상 추론됨을 확인했다.


8. 단독 YOLO 검증 기준
----------------------

Pruned+KD single 모델, 이미지 1장, conf=0.30, NMS=0.40 결과:

  MODEL_SANITY       : 0
  classes            : 1 (output channels=65)
  input              : 3x1024x1024, scale=1, zero=0
  DMA runtime plan   : 약 28.07 MiB
  DMA64 utilization  : 약 43.85%
  inference-only     : 약 196.47 ms, 약 5.09 FPS
  compute E2E        : 약 1140.35 ms, 약 0.877 FPS
  process peak RSS   : 약 29.88 MiB

예제 실행 명령은 YOLO_INFERENCE_EXAMPLE.txt를 참고한다.


9. 확인 사항
-------------------------------------

  - 현재 pipeline_main.c는 FIRST_FRAME=0, LAST_FRAME=0으로 JPEG 한 장의
    acquisition 경로를 우선 시험하도록 설정됨
  - 통합 후 JPEG -> YOLO -> ROI -> pose_acquire -> q,t 순서로 먼저 검증
  - acquisition 한 프레임 성공 후 tracking loop 범위를 확장
  - 최종 바이너리는 PolarFire용 RISC-V lp64d로 빌드해야 함
